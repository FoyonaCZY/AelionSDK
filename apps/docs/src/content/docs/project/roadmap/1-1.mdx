## Goal

Turn the explicitly uncertified boundaries of `1.0.0-rc.1` into certified, verified capability, so
applications can deploy to real devices with a documented fallback story.

## Scope

| #     | Item                                 | Priority | Size | Notes                                                                                                                                                                                                                       |
| ----- | ------------------------------------ | -------- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1-1 | **Real-device certification matrix** | P0       | L    | Physical Safari iOS/macOS, Chrome/Edge Android and system WebViews via a device farm; reproducible device × codec evidence bound to a source manifest. Today the docs state physical Safari/iOS/Android need certification. |
| 1.1-2 | **Software codec fallback**          | P0       | L    | WASM H.264/HEVC/AAC/VP9 decode and encode where hardware is absent (Safari/iOS, Android WebView). Requires the codec-strategy decision; replaces "unsupported" with a documented lower-tier contract.                       |
| 1.1-3 | **Long-session durability**          | P0       | M    | Service-worker/PWA background rendering so long jobs survive page lifecycle limits, plus stronger recovery for interrupted export. 24h+ soak and restart evidence.                                                          |
| 1.1-4 | **New containers and image formats** | P1       | M    | MOV/MKV/TS import; AVIF/JPEG-XL decode; PNG image sequences. Extends the existing MP4/WebM and PNG/JPEG/WebP/GIF surface.                                                                                                   |
| 1.1-5 | **Diagnostic message localization**  | P1       | S    | Multilingual messages over the existing diagnostic-code system.                                                                                                                                                             |
| 1.1-6 | **Hardened fuzzing and long soak**   | P1       | M    | Extend fast-check fuzzing to export bytes, media parsers and transaction sequences; continuous 24h+ session soak with automatic recovery verification.                                                                      |

## Acceptance

- Every capability is exercised on the target matrix and produces the evidence artifacts that the
  release gate requires.
- WASM fallback and hardware paths produce **identical** Project and Render IR semantics; only the
  declared execution tier differs.
- New containers/formats pass index, decode, preview, export and migration checks with bounded
  resource admission.
- The version passes the standard prerelease gates (`alpha` → `beta` → `rc` on `next`).

## Risks and dependencies

- Blocked on the **software codec strategy** decision; scope of 1.1-2 and the package-size budget
  both depend on it.
- Device-farm certification is recurring cost and needs a locked device set per release.
- Long-session durability may be partially blocked by platform lifecycle rules on iOS Safari;
  remote export remains the durability ceiling for jobs that exceed it.
