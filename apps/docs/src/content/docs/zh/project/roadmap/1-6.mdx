## 目标

把单页编辑变成协作、服务连接的平台，同时保持引擎确定性、公开契约显式。

## 范围

| # | 条目 | 优先级 | 规模 | 说明 |
|---|------|--------|------|------|
| 1.6-1 | **协作编辑层** | P1 | L | CRDT/OT 操作同步、presence、实时光标/选区、评论标注，接入现有 transaction/undo/revision 体系。 |
| 1.6-2 | **Remote Export Protocol 2.0** | P1 | L | 可续传、带宽自适应、多 provider 编排和参考云端渲染契约，扩展现有的 content-addressed、幂等 1.0 协议。 |
| 1.6-3 | **插件/素材市场协议** | P2 | M | 公开目录协议、版本范围解析、第三方效果的签名分发，基于现有 Material 签名/信任/registry 模型。 |
| 1.6-4 | **素材语义检索** | P2 | L | embedding 索引和对素材库的自然语言搜索（与 1.5-6 共享表面）。 |

## 验收

- 协作保持事务不变量：每个远程操作都是经过校验、可逆的变更，冲突检测与本地规则一致。
- 没有协作后端时，presence 和评论功能优雅降级。
- 协议版本可协商、可版本化；1.0 客户端保留文档化的迁移路径。
- 远程导出在最后一个持久检查点精确续传，并校验结果字节/哈希。

## 风险与依赖

- 依赖**协作技术**决策（CRDT vs OT），以及它如何与现有 revision-bound 持久化调和。
- 协作同步是确定性风险最高的地方；golden/soak 证据必须覆盖并发编辑回放。
- 1.6-4 与 1.5 共享；排序应让 provider 抽象只落地一次。
