## 目标

加深编排和音频工程表面，让产品能够覆盖多机位拍摄和严肃的音频清理，而无需离开 SDK。

## 范围

| #     | 条目                    | 优先级 | 规模 | 说明                                                                                  |
| ----- | ----------------------- | ------ | ---- | ------------------------------------------------------------------------------------- |
| 1.4-1 | **多机位编辑**          | P1     | L    | 同步组（波形/时间码对齐）、角度切换和多机位播放模式，基于现有时间映射和轨道模型构建。 |
| 1.4-2 | **逐轨音频效果链**      | P1     | M    | EQ、压缩器和去噪器作为可插拔的逐轨处理节点，超越当前的 fades/ducking/master 设置。    |
| 1.4-3 | **语音增强与去噪**      | P1     | M    | 实时去噪和去混响作为效果链中的节点类型；基于 provider，端上/云端决策保持开放。        |
| 1.4-4 | **项目模板**            | P2     | M    | 参数化 Project 实例化：Project 充当模板，带可编辑的模板参数。                         |
| 1.4-5 | **高级片段波形/元数据** | P2     | S    | 更丰富的逐片段分析元数据，暴露给时间线和预览。                                        |

## 验收

- 多机位同步产生采样级精确对齐，并带经过校验的时间码处理；角度切换是事务性的。
- 效果链节点与音频管线其余部分共享一个处理接口，内存和取消语义有界。
- 模板实例化是确定性的：同一模板和参数总是产生相同的 Project。
- 所有新实体遵循完整执行路径（builders、validation、migration、IR、preview、export、types、docs）。

## 风险与依赖

- 1.4-1 依赖 1.2 的分析输出做波形/时间码同步，并依赖 Render IR 结构。
- 音频效果图会推高 CPU 成本；1.1 的资源预算和浸泡工作必须先行到位。
- 模板参数可能需要加性的 schema 扩展；保持可选并经校验。
