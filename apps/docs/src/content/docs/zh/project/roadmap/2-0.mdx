## 目标

`2.0.0` 是第一个**稳定**的 AelionSDK 发布。它应用在 `1.x` 次版本期间推迟的破坏性变更，冻结公开 API，并提供从 1.x 迁移的一等路径。2.0 之后，破坏性变更遵循文档化的弃用窗口，而不是每次主版本一次性释放。

## 范围

| #     | 条目                                    | 优先级 | 规模 | 说明                                                                                                              |
| ----- | --------------------------------------- | ------ | ---- | ----------------------------------------------------------------------------------------------------------------- |
| 2.0-1 | **Project schema v2 与 Render IR 整合** | P0     | L    | 把 1.x 期间积累的 schema/IR 增量（字幕、时间重映射、效果链、模板、多机位）整合成连贯模型；移除仅 1.x 的废弃形态。 |
| 2.0-2 | **包与 API 表面清理**                   | P0     | L    | 一次性破坏性清理导出、类型名和包边界；API snapshot 门禁冻结结果。                                                 |
| 2.0-3 | **认证收官**                            | P0     | M    | 在完整设备矩阵上收尾 HDR 和 WebGPU 认证；剩余的 1.0 "未认证"边界要么被认证，要么被显式移除。                      |
| 2.0-4 | **稳定发布语义**                        | P0     | S    | 第一个 `latest` dist-tag 发布，并附书面 API 稳定性与弃用窗口政策。                                                |
| 2.0-5 | **v1 → v2 迁移工具**                    | P0     | L    | 升级 `aelion-migrate`，从 v1 产出经过校验的 v2 Project 和带版本的损失报告，复用现有严格模式理念。                 |
| 2.0-6 | **全量重新认证**                        | P0     | L    | 为冻结的源清单重新生成完整证据集，包括设备矩阵、golden 数据、浸泡和包可复现性。                                   |

## 验收

- 每个 1.x 功能都有文档化的 v2 表示；任何破坏性变更都不带静默语义变化。
- v1 → v2 迁移是确定性的、在可能处可逆的，并像现有 WebAV/Diffusion 适配器一样输出损失报告。
- `2.0.0` 通过完整发布门禁，以 `latest` + provenance 发布。
- 2.0 之后的政策从第一个 2.x 次版本开始执行：任何破坏性变更都强制要求弃用窗口、changelog 和迁移文档。

## 风险与依赖

- 2.0-1 是风险最高的整合：schema/IR 变更必须保持渲染语义或 fail closed。golden 数据和迁移回放是安全网。
- 2.0-2 触及每个包；API snapshot、narrative-coverage 和包 README 门禁让表面保持诚实。
- 2.0-3 依赖 1.x 认证工作（1.1 真机矩阵、1.2 WebGPU 等级）真正落地并保持绿色。
