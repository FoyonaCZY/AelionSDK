## 范围

AelionSDK `1.0.0-rc.1` 提供了一个以浏览器为优先的剪辑、预览、播放和导出引擎，并带有经过认证的自动化矩阵。通往 `2.0` 的路径是一系列**向后兼容的 `1.x` 次版本**，逐步补充能力和认证，随后是一个单一的 **`2.0` 稳定化发布**，应用沿途收集的破坏性变更并冻结 API。

## 版本规则

- `1.x` 次版本严格**累加**：新增能力、格式、绑定、后端和认证，不破坏公开 API、Project/Material 协议或资源所有权规则。次版本可以用可选、经过校验的字段扩展 schema。
- 破坏性变更**推迟并在 `2.0` 统一收集**，包括 schema/IR 整合、API 表面清理，以及任何在 1.x 规则下无法保持语义的决策。
- 每个版本都保持现有纪律：代码、公开契约、文档、CI/证据和发布产物必须一起落地（见[当前状态](/AelionSDK/zh/project/status/)）。
- 每个次版本都遵循预发布节奏（`alpha` → `beta` → `rc`，使用 `next` dist-tag）。第一个 `latest` 稳定版是 `2.0.0`。

## 跨版本决策

这些选择跨越多个版本，应在受影响的次版本启动前确定：

1. **软件编解码策略** — 自研 WASM 解码/编码器，还是引入重型依赖（ffmpeg.wasm 一类），还是只依赖平台编解码并带明确的降级契约。它决定 [1.1](/AelionSDK/zh/project/roadmap/1-1/) 的回退工作和包体积预算。
2. **智能形态** — 端上优先（隐私、离线）还是云端优先（模型质量）。它定义 [1.5](/AelionSDK/zh/project/roadmap/1-5/) 的 provider 边界，以及远程协议是否承载模型推理。
3. **协作技术** — CRDT（Yjs 一类）还是服务端 OT。它决定 [1.6](/AelionSDK/zh/project/roadmap/1-6/) 的协作层如何接入现有事务和 revision 体系。
4. **稳定语义** — `2.0.0` 是第一个 `latest` 发布并冻结 API。在 1.6 预发布窗口关闭前确定弃用窗口和迁移契约。

## 验收

路线图条目只有在代码、公开契约、文档、CI/证据和发布产物全部存在时才算交付。认证声明遵循[兼容性与部署](/AelionSDK/zh/production/compatibility/)中的词汇：automated、supported 和 certified 含义不同，证据必须与声明匹配。
