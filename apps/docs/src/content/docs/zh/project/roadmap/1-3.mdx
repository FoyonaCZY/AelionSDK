## 有顺序的范围

| 顺序 | 项目                   | 验收条件                                                                              |
| ---- | ---------------------- | ------------------------------------------------------------------------------------- |
| 1    | **包与运行时边界审计** | 依赖方向、生命周期所有权、Worker 资源、SSR 行为和 exports 都有文档与门禁              |
| 2    | **真实消费者 fixture** | Vite、Webpack/Rspack、Next.js、headless Node 与 no-build ESM 完成安装、构建和运行测试 |
| 3    | **包体积预算**         | 每个包和代表性应用的 gzip 预算在回归时阻断 CI                                         |
| 4    | **框架绑定**           | React/Vue/Svelte 只在已经验证的 SDK 边界上提供轻量生命周期/状态适配                   |
| 5    | **参考 UI 组件**       | 提供可访问的时间线、属性、媒体、播放器和字幕基础组件，而不是完整编辑器产品            |
| 6    | **有证据的热点优化**   | SIMD/WASM 只在语义不变并具备 benchmark/golden 证据时合入                              |

框架绑定必须晚于边界与消费者验证，否则每个绑定都会固化尚未稳定的生命周期决定，并放大迁移成本。
