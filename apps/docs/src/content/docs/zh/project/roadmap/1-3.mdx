## 目标

通过提供框架绑定、部署路径和参考 UI 构建块，让引擎可直接用于产品，但不构建完整产品。

## 范围

| #     | 条目                      | 优先级 | 规模 | 说明                                                                                                                                                                          |
| ----- | ------------------------- | ------ | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.3-1 | **官方框架绑定**          | P0     | L    | `@aelionsdk/react`、`@aelionsdk/vue` 和 `@aelionsdk/svelte`，带 Composition/session 生命周期 hooks 和响应式状态桥接。README 承诺 framework-agnostic，这里在之上提供一等绑定。 |
| 1.3-2 | **CDN 与无头用法**        | P1     | M    | 无构建 ESM CDN 入口、安全的 Node/SSR 降级、已验证的 tree-shaking。                                                                                                            |
| 1.3-3 | **参考 UI 组件**          | P1     | L    | 可组合的时间线、属性面板、媒体浏览器、播放器控制和字幕编辑器——不是完整产品，而是从 `editor-demo` 演进而来的可插拔构建块。                                                     |
| 1.3-4 | **构建集成对齐**          | P2     | S    | 把 Webpack/Rspack/Next.js/CDN 的 runtime-asset 支持对齐到 Vite 插件水平。                                                                                                     |
| 1.3-5 | **包体积预算**            | P1     | M    | 逐包 gzip 预算、子路径导出、side-effect 声明审计，并在 CI 中强制执行包体积。                                                                                                  |
| 1.3-6 | **热路径 SIMD/WASM 优化** | P1     | M    | 用 SIMD/WASM 在现有 API 之后重写重采样、矩阵和颜色热路径。                                                                                                                    |

## 验收

- 每个绑定包与引擎包遵循相同的发布纪律（契约、文档、证据、产物）。
- 参考组件支持键盘访问并文档化 ARIA 契约。
- 包体积检查在回归时让 CI 失败，与现有 api:snapshot 门禁一致。
- SIMD/WASM 热路径位于当前公开 API 之后；行为不变，基准随发布一起交付。

## 风险与依赖

- 1.3-5 需要先做基线审计再定预算；过早加预算会阻塞能力次版本。
- 1.3-6 依赖 1.1 的编解码/后端决策，以保证优化目标稳定。
- 框架绑定放大维护成本；API snapshot 和 narrative-coverage 门禁适用于每个新包。
